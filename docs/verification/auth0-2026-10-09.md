# Auth0 profile verification — 9 October 2026

The maintainer approved adding Auth0 before postponed work. `authentication.provider`
now accepts `auth0` alongside `oidc` and lab-only `fixture`. No dependency or SDK
wheel changes. Auth0 shares the existing bounded RS256 verifier and trusted
subject bindings, without online introspection. `oidc` retains mandatory
per-request introspection. Auth0 configuration rejects introspection fields and
lifetimes above 300 seconds. Production still requires verified HTTPS.

The behavior follows Auth0's documented signature/audience/scope validation.
Issuer/custom-domain and JWKS URLs remain explicit trusted configuration. Scope
and API audience must be configured in the Auth0 tenant. Already-issued JWTs can
remain valid until expiry after provider logout; binding policy updates require
config delivery and replica restart. See [identity setup](../identity.md) and
[the example](../../configs/auth0.example.json).

TDD: eight new unit cases failed with unsupported provider/configuration before
implementation; 23 existing/config-negative cases passed. Shared rotation,
unknown-key cooldown, algorithm confusion and expired-cache outage tests now
exercise both profiles. Auth0 subject/audience shapes, invalid claims/scope,
binding disablement/not-before, short lifetime, factory selection and HTTP
authorization-before-body are covered. Full local suite: 237 passed, one benign
Starlette deprecation warning. Independent read-only review found no important
defect; its focused OIDC/HTTP suite passed 37 tests.

The added real identity contract test switches both immutable replicas to Auth0
JWT mode, consumes real RS256 tokens over TLS from the owned Keycloak issuer,
approves across replicas, verifies owner isolation/frozen billing and disables
a binding through actual private config delivery/restart. This is local JWT
integration evidence, **not live Auth0 tenant certification**. No Auth0 tenant,
customer credentials or paid inference is contacted.
