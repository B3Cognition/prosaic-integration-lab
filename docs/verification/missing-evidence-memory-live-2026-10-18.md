# Fresh missing-evidence memory comparison — 2026-10-18

The four authorized held-out samples completed with known usage and were
independently reconciled against native receipts and recorder observations.
Memory provided no observed correctness or request/tool efficiency benefit on
this case. The smaller model failed both arms; the larger model passed both.
This is one case and one trajectory per cell, not a general memory efficacy claim.

## Experiment

One new missing-evidence case × two unchanged models × memory off/on.
The current two-row index has one available required-authority fact and a
higher-revision observer row for the absent required-authority fact. The correct
decision is insufficient. Prior approval history is untrusted context, not a
current source. History and trusted metadata were frozen before current case
and private-answer authoring; unrelated and foreign-tenant decoys were excluded.

Both enabled arms retained the one relevant historical episode. Both disabled
arms received none, so both model pairs actually compare recall exposure.
Memory, case, prose, settings and quotations were not adjusted after quotation
or live results. Model/arm order was smaller off/on, larger on/off. Both arms use
typed evidence, bounded recovery and opt-in shared continuation budgeting.

The installed candidates are Runtime0.9.8+diagnostics.1, Lab0.5.1+diagnostics.1
and public Harness0.9.4. Their exact bytes and SDK payloads were re-audited against
the [offline qualification](response-faults-2026-10-18.md). The same hash-locked
counter libraries, descriptors, model/profile fingerprints and19serving/counter
asset files remain qualified and unchanged. All four mandatory plans admitted
and passed synthetic native execution, pure preflight and network-denied replay
before live dispatch. There were no live development probes or reruns.

## Results

| --- | --- | --- | --- | --- | --- |
| Smaller 7B | Fail | Fail | 4,874 /5,482 | 4 /4 | 2 /2 |
| Larger 27B | Pass first attempt | Pass first attempt | 2,954 /3,175 | 2 /2 | 1 /1 |

The smaller model fetched both the verifier and observer rows in each attempt.
Its fact labels and citations correctly reported only the available verifier
fact, but its decision was approve instead of insufficient. Public corrective
feedback explicitly identified required-authority absence; the permitted second
attempt repeated the same wrong decision in both arms. This is a decision and
feedback-following failure after successful lookups, not a fact-field formatting,
citation, native tool transport, timeout or admission failure. The workflow gate
rejected the unsupported decisions rather than accepting a model approval.

The larger model fetched only the available verifier row and returned the
correct insufficient decision and fact/citation fields immediately in both arms.
Within each model pair, requested record sets match. All six tool calls returned
validated ok outcomes. Every answer-producing request ran; no continuation was
refused and no new unknown reservation or limit overrun occurred.

Recall added608tokens for the smaller model and221for the larger,829in total.
It saved no request, tool call or correction. Observed elapsed seconds were
20.1/15.4 off/on for the smaller model and110.5/102.6 for the larger. These single
ordered trajectories do not establish a latency benefit; sampling and cache
effects remain uncontrolled. This experiment neither proves memory useless in
other tasks nor resolves broader model capability differences.

## Budget and diagnostics findings

The smaller off arm proposed one conservative input bound of1,212tokens against
a planning quotation of1,152. Shared continuation admission accepted it under
the unchanged outer allowance. Independent prefix checks verified paid usage
plus each proposed input/output reservation fitted the8,192-token case limit.
This directly exercises the generic quotation-overage fix; the old quotation
refusal confound does not explain this comparison's identical paired outcomes.

All12native responses were classified as message/unsupported usage by the new
diagnostics. Numerical input/output/total quantities were available, internally
consistent, within the counted bounds and reconciled to receipts. Unsupported
extended usage details are distinct from unknown numerical usage; this is not
a full usage-schema, pricing or billing qualification. The bounded diagnostic
contract does not retain arbitrary usage field names, so no narrower cause is
claimed. No malformed-response or provider-error envelope occurred in this run,
and it cannot retrospectively explain the prior unknown HTTP200 incident.

## Next milestone

The operational baseline is ready for the next offline milestone; memory should
remain experimental and the smaller model must remain behind evidence validators.
The next useful work is provider-neutral typed multi-agent handoffs and full
trajectory evaluation using the existing Runtime/Harness primitives: task/result
schemas, planner/worker/critic roles, conflicting or incomplete evidence,
bounded rework or human escalation, shared budgets and receipt-only recovery.
Measure where a trajectory fails, not only its final answer. This addresses the
coordination and observability stages of the
[original roadmap](https://www.kdnuggets.com/the-roadmap-to-mastering-agentic-ai-systems-in-2026).

This is a recommendation for an offline qualification milestone, not permission
to run more models or a claim of production autonomy. Broader independent cases,
additional providers, approval/rejection controls, stale sources and longer
trajectories remain necessary for general efficacy claims. No further model-
specific prompt adjustment is justified by this one paired case.
