## Opt-in execution profile

`freeze --execution-profile bounded-120s-v1` freezes the longer deadline
independently of generation guidance. It allows 120 seconds per model call,
150 for the initial answer, 270 for critic plus independent author, and 450 for
one retrieval/answer/review sample. These enclosing limits include bookkeeping.
The new profile clips sample and stage limits to the remaining shared allowance;
the preflight retains its overall 3,600-second limit. Smaller explicitly supplied
stage lifetimes remain reductions.

Omitting this option retains `bounded-60s-v1` and prior limits 60/120/120/300.
Default dataset shapes and legacy binding versions remain unchanged. The longer
profile changes policy/adapter/validator identity, so it cannot silently resume
an existing 60-second run. No timeout override is available at run time.

The generation module, prompts, schemas, scorer, retrieval and source validation
remain unchanged. Canonical strict grounding, scope/provenance and output-byte
limits still apply. Model limits remain 4,096 output tokens, no tools/retries,
one request per stage, and at most three requests/98,304 reserved tokens per
sample. Runtime, Harness and the Castle adapter/worker are unchanged.
