# Explorer implementation verification — 2026-10-25

This is local implementation evidence for the post-0.6.2 Explorer. It is not a
release, Linux/database qualification or new live model benchmark. All inference
responses used here were owned synthetic fixtures. Released SDK pins and
historical benchmark/release evidence remain unchanged.

## Behavior and boundaries

The implementation bundles five React Flow chapters, user/developer inspection,
the equivalent list view, eight deterministic playback scenarios and a localhost
single-agent execution coordinator. The host consumes public Runtime 0.9.8 via
its CLI. Harness workflow execution remains in the existing separate service.

Review found and fixed two issues: process cancellation could leave descendants
after the Runtime leader exited, and a historical receipt could clear a pending
request identity. Regressions exercise real owned process groups and exact-ID
retry/reset rules. Follow-up review found no further actionable issue in the
HTTP/launcher, durable accounting, packaging, CI or guide boundaries.

Additional audit regressions verify timeout blockers despite known dispatch
counts, native token observations above the API cap, and unresolved symlink
references. Browser interaction caught two issues beyond unit coverage: a React
Flow selection feedback loop and native `fetch` called with an invalid receiver.
Both were fixed and are exercised by the reusable Chromium suite.

## Visual inspection

Used the requested Taste v2 app workflow, upstream v2.1.5, pinned commit
`12af471f627f866411b4bd785b19646d3672784c`.
The dealt style is **Framed sheet**, seed **1548770335**, with no redraws.
Its face is the pale technical workspace, locally loaded IBM Plex Sans, and teal
selection data. The signature element is the Markdown → permission → receipt
handoff graph, using actual Prosaic components rather than generic dashboard data.

Each chapter asks one question: how the components hand off work; what one agent
may do; where workflow review pauses/resumes; when a pool may switch; and which
evidence supports completion. Each node shows inputs, outputs and authority.

Three production-browser inspection rounds were opened and examined at
1440×900, 768×1024 and 390×844. The initial pass found a page-level `data-ui`
wrapper, strong graph borders and absent data hue; these were fixed. Tablet
inspection led to stacking the inspector under the full-width graph. Phone
inspection led to a readable initial list with an optional graph. Final measured
result: **0 FAIL / 0 WARN**, IBM Plex Sans loaded. No inspector allowances were
used. The source lint's `box-shadow: none` warning is a false positive for removing
React Flow's default shadow; production measurements confirm no shadow finding.

App critique:

1. The largest region traces the chapter's handoff; the title states its question.
2. Desktop graph/inspector align to the sheet; tablet stacks cleanly, without the
   earlier narrow graph column. Phone list rows use the same content.
3. Teal marks selected data and incident edges; navigation stays neutral. The
   bundled typeface and drawn document mark establish the product on first view.
4. Version numbers match the manifest. Policy ceilings match the CLI command.
   Allowance numbers use mixed units; unknown reservations are labeled as counts.
5. Missing usage reads “Unknown,” never an invented zero; empty receipts state
   that no result exists. There are no vanity counts or KPI panels.
6. Nodes carry their own labels; edges avoid labels and use selection hue.
   Long orthogonal paths remain an overview tradeoff; selecting/list inspection
   exposes the exact contract without needing to infer authority from a line.
7. Navigation folds behind Chapters. Phone content is readable at initial load;
   choosing the optional graph requires zoom/pan for detail. Long live policy and
   receipt sections stack vertically, with no page-level horizontal overflow.

Simulation states are illustrative and permanently labeled. Replace them only
with actual receipts when presenting measured execution; do not present playback
as live provider evidence. Bundled font licenses are retained in both source and
generated assets. Exact MIT, ISC and BSD notices for all 17 bundled JavaScript
packages are included separately; development dependencies are excluded.
