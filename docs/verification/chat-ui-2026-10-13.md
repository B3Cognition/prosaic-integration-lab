# Browser conversation UI — 2026-10-13

The approved simple UI is served at `/chat` and calls the existing authenticated
conversation APIs. It supports message history, new conversations, workflow
choices and explicit approval, usage counts, status refresh and recovery
inspection. It renders text without interpreting model/user content as HTML.
Inline script/style hashes restrict the page's content security policy; all
requests stay on the service origin. API tokens remain in browser memory.

`python -m lab_runner.chat` keeps an owned loopback PostgreSQL fixture and chat
service running. A single-use ten-minute launch code delivers the fixture token
only to a matching-origin browser and is removed from the address bar. The page
can alternatively connect with a manually supplied authorized token. Ctrl+C
stops the service and verifies cleanup of exact-owned engine resources.

Live inference requires `--live-local`. The approved local Qwen profile reads
its credential from a private API key file. A nonretrying gateway enforces a
shared launch-wide provider allowance (32 requests by default), literal loopback
provider URLs, bounded payloads, disabled proxy inheritance and no redirects.
It rejects browser-originated and non-JSON requests before credentialed dispatch.
Workflow tools remain synthetic Lab operations. No hosted provider was contacted.

## Observed verification

- Full unit/functional suite: 953 passed, zero skips; one existing Starlette
  deprecation warning.
- New boundary tests: public GET `/chat` exposes no credential or session data;
  conversation APIs remain authenticated; POST/nearby paths do not inherit the
  shell exception.
- One-use bootstrap rejects wrong origins/codes and replay. Gateway tests use
  a real synthetic loopback provider, reject browser/plain-text requests without
  consuming allowance, refuse redirected credential dispatch and stop after the
  shared request limit.
- Actual browser with an owned PostgreSQL 16 synthetic stack: remembered Brno,
  adopted correction to Prague, recalled Prague, offered ordered player choices,
  selected the second player and displayed a separate approval prompt. Approval
  completed the workflow with seven conversation calls and two workflow calls.
  The API token input and URL fragment were empty after connection.
- Actual browser with the approved local Qwen 27B profile: one real provider
  request completed; a short greeting received a valid assistant response in
  about 18.7 seconds. The page rendered ordinary text blocks as readable prose.
- Browser regression: an over-limit message was rejected before inference;
  the corrected composer released its replay state and accepted a subsequent
  valid message. Uncertain execution/transport failures retain the exact original
  request for explicit replay; confirmed pre-admission rejections allow editing.
- Temporary synthetic and live test stacks reported verified owned cleanup.

These are local browser and installed-public-SDK checks. They do not replace the
four-cell release matrix or hosted-provider qualification. No changes were made
to upstream SDK engines, public API contracts, authentication identities or
approval authority. The persistent user-facing launcher is intentionally left
running separately from the cleaned-up test stacks.

See the [browser recipe](../../README.md#converse-in-the-browser). Reloading loses
the in-memory token; use a fresh launch or manually reconnect. Private launch
files, DSNs, credentials and user conversations remain under ignored `.lab/`
directories and are not part of this evidence document.
